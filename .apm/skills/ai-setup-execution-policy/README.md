# Политика выполнения

Навык помогает задать одну приватную политику пользователя для нескольких
проектов. В ней остаются точные модели, цены, лимиты и результаты
квалификации. Проект хранит только классы задач, критерии качества и проверки.

## P0: без Python и POSIX

Если скрипты запускать нельзя, создайте пользовательское ядро и проектное
уточнение средствами агента по образцам из `assets/`. Проверьте приватность
ядра, ссылки на маршруты, критерии и обязательные свидетельства. Оставьте
`automatic = false`: такой результат полезен, но не даёт автоматический допуск
без P1-проверки. Пакет передачи также можно заполнить и проверить вручную по
разделу «Передача между сессиями» в справке навыка.

## P1 и P2: необязательная автоматизация

P1 требует Python 3.11 или новее. Он не устанавливает пакеты и не использует
сеть. P2 требует POSIX-среду и только копирует P1-скрипт с образцами в целевой
проект. Сначала проверьте доступность соответствующей среды. При её отсутствии
оставайтесь на P0 и отметьте отсутствие автоматической проверки.

В POSIX-среде установите средства в целевой проект:

```bash
.apm/skills/ai-setup-execution-policy/scripts/install-execution-policy-tools .
```

Затем явно создайте образцы. Путь пользовательского ядра выбирает пользователь.
Если он находится внутри Git-репозитория, `init-user` требует исключить файл из
Git или передать отдельный явный флаг.

```bash
tools/execution-policy init-user --output <приватное-пользовательское-ядро>
tools/execution-policy init-project --output execution-policy.project.toml
tools/execution-policy check \
  --user-core <приватное-пользовательское-ядро> \
  --project-overlay execution-policy.project.toml
```

Команда `prepare-qualification` создаёт черновик свидетельства с отпечатком
текущей политики. Его нельзя пометить как допуск к автоматическому применению,
пока не заполнены фактические маршруты, результаты каждого критерия и каждого
обязательного свидетельства, а для корневой задачи — след внешней интеграции.
При эскалации запись отдельно хранит её причину и сохранённые результаты.

Пакет передачи проверяют отдельно:

```bash
tools/execution-policy check-handoff --input handoff.md
```

Пакет хранит итог продолжения и признак подтверждённой экономии. Если новой
сессии потребовалась полная стенограмма или повторное выполнение этапа, средство
не допускает отмечать передачу как успешную или экономию как подтверждённую.

Навык не управляет уже начатой корневой сессией. Он может подготовить и
проверить основания, которые использует внешняя интеграция.
