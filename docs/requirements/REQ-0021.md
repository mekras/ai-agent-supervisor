# REQ-0021. Временное хранение данных запусков подагентов

## Требование

Данные новых запусков подагентов хранятся локально вне Git, пока нужны для
выполнения родительской задачи и проверки результата. После завершения задачи
рабочая процедура агента автоматически вызывает завершение хранения, а
запускатель удаляет временные данные каждого запуска этой задачи.

Длительное хранение включается только по явному запросу пользователя для
конкретного разбора или эксперимента. Прежние журналы, их отслеживание
и история Git не изменяются этим механизмом.

## Критерии приёмки

1. Оба запускателя выбирают каталог в порядке `--out`,
   `policy_runtime.run_records_dir`, `.local/subagents`. Каждый запуск получает
   собственный каталог, содержимое которого исключено из обычного `git add`.
   Продуктовые роли оснастки сохраняют своё прежнее размещение и отслеживание.
2. Ответ и сведения исполнения доступны до проверки и использования результата.
   Запись и проверка приёмки сохраняют связь с конкретным запуском и ответом.
3. Рабочая процедура завершает хранение всех запусков задачи, включая
   неуспешные и отвергнутые. Для успешного исполнения требуется приёмка или
   содержательный отказ. Для неуспешного допускается завершение без приёмки.
4. Очистка проверяет владельца данных, терминальный статус и для класса
   исполнения завершение процессов. Подменённый путь, ссылка, посторонний
   файл, чужая блокировка или неполная приёмка останавливают удаление.
   Общий каталог, соседние запуски и прежний формат записей не очищаются.
5. `--retain-for` требует непустую причину из явного запроса пользователя.
   При завершении данные сохраняются. По окончании согласованной цели
   `--release-retained` позволяет удалить их тем же проверяемым способом.
6. При прерывании родительской сессии до завершения хранения данные остаются
   для продолжения. Запускатель не определяет окончание всей задачи по выходу
   подагента и не обещает очистку при пропуске рабочей процедуры.

## Источник и статус

- Источник: согласие владельца от 2026-10-12 на временное хранение, удаление
  после задачи и длительное хранение только по явному запросу.
- Статус: принято.
- Реализация: запускатели и рабочая процедура подготовлены. Детерминированная
  проверка использует управляемые исполнители. Поведение модели по процедуре
  отдельно не проверялось.
