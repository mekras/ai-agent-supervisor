# REQ-0054. Размещение файлов, которые создаёт агент

## Статус и источник

Требование **принято** владельцем проекта ответом «Подтверждаю правило».
Правки в других проектах выполняет установленный продукт в рамках поручений
об их настройке или исправлении. Классификация —
`specification_change` по [порядку изменений](../decisions/DR-0010.md#порядок-изменений).

Пользователь сообщил о лишних временных файлах, отчётах и состоянии в целевых
проектах и о размещении нужных файлов в неподходящих местах. В сессии
`01a20310-103d-7af3-ac63-af258210e796` он поручил включить автоматическое
обучение в Центре управления проектами. Агент создал журнал в каталоге Git
и привязал к нему проверку режима в инструкциях проекта. Перед записью
агент прочитал [справку о состоянии наблюдений][usage-state], которая прямо
разрешала этот путь.

Цель — пользователь получает нужные файлы на предусмотренных местах,
а состояние и материалы работы агента не загромождают целевой проект.

## Требование

Перед созданием файла в ходе работы коллекция должна требовать от агента
установить, нужен ли файл для поручения, и выбрать место по его назначению.
Это правило распространяется на записи, которые агент поручает подагентам
или выполняет через инструменты коллекции.

- Файл проекта или запрошенный результат создаётся в месте, заданном
  поручением, структурой проекта или его применимыми правилами. Для отчёта
  сначала проверяется основание для создания файла по [REQ-0026](REQ-0026.md).
  История диалога и вывод инструментов служат следом работы, когда отдельный
  файл не нужен.
- Если для текущей работы нужен временный файл, по умолчанию агент
  использует уникальный каталог в системной временной области вне проекта.
  Агент удаляет свои временные файлы после работы, в том числе после
  обрабатываемой ошибки. Если проверка требует временной записи рядом с
  проектным файлом, агент использует предусмотренное процедурой место и
  убирает созданные им временные файлы после проверки.
- Состояние между запусками, рабочие журналы и резервные копии создаются,
  когда их требует поручение или применимая процедура, в предусмотренном
  пользовательском хранилище вне проекта либо в явно отведённом месте
  проекта. Если без записи можно продолжить, агент продолжает без неё.
  Если запись необходима, а место не определено, агент уточняет только
  место хранения. Игнорирование пути системой контроля версий не назначает
  ему роль хранилища.
- Каталоги метаданных системы контроля версий, включая фактический каталог
  Git связанного рабочего дерева, используются для данных этой системы.
  Коллекция не использует их для своих отчётов, журналов, состояния, копий
  восстановления и кешей. Разрешённые операции с настройками самой системы
  контроля версий выполняются по правилам проекта.

При смене места хранения для действующей настройки агент сохраняет
существующие данные и проверяет, что читатели и писатели используют один
путь. Удаление или перенос прежних файлов выполняется в согласованной области.

## Критерии приёмки

1. По итогам проверки без требования сохранить файл агент отвечает в диалоге.
   Само указание папки отчётов не приводит к созданию папки или файла.
   При явном запросе файла агент сохраняет его в предусмотренном месте.
2. Команда требует передать ей временный файл. При успехе и обрабатываемой
   ошибке создания файлов в целевом проекте нет, созданный временный каталог
   убран, ранее существовавшие файлы сохранены.
3. При включении самообучения с предусмотренным хранилищем журнал
   создаётся по этому пути и следующий запуск читает тот же журнал.
   Проверка флага по [REQ-0015](REQ-0015.md) продолжает работать. Если место
   не предусмотрено, запуск без записи остаётся доступным для разового
   разбора, а при настройке постоянного режима агент запрашивает место.
4. В обычном репозитории и связанном рабочем дереве журнал, состояние и кеш
   агента появляются только в предусмотренном хранилище за пределами
   фактических каталогов Git. Запрошенная настройка самого Git по-прежнему
   работает. Игнорируемый путь без назначения хранилища остаётся пустым.
5. При согласованном переносе журнала сохраняются флаг включения,
   наблюдения и отметки о разобранных случаях. Следующий запуск читает
   сохранённые данные и дополняет журнал по новому пути.

## Связь с реализацией

Общее правило задано в [размещении файлов][placement]. Оно доступно при
обязательном чтении навыка общения и при [контроле работы][work-control].
[Справка о хранилище наблюдений][usage-state] и
[настройка самообучения][learning-setup] согласуют место и проверку флага.
[Аудит правил][audit] проверяет назначение файлов и направляет исправление
в пределах поручения. [Договор записи применения обучения][tooling]
задаёт исполнимую проверку пути для состояния и резервной копии.

Отчёт и временные входы проверяются в
[сценариях формы результата][output-cases]. Настройка с назначенным
хранилищем и без него проверяется в [сценариях самообучения][learning-cases].
[Контрактные проверки скрипта][learning-contract] проверяют отклонение
каталога Git, в том числе отдельного каталога метаданных.

Проверка кода зависимости `ai-dev-team` обнаружила ещё две записи в каталог
Git: возобновляемое состояние полной перепроверки и кеш выборочных проверок.
Аудит относит такие находки владельцу пакета. Исправления в исходниках
`ai-dev-team` и обновление установок в других проектах не входят в реализацию
в этом репозитории.
