# REQ-0002: Граница проекций APM и Git

- **Статус требования:** принято 2026-07-30
- **Состояние реализации:** выполнено
- **Уровень:** функциональное требование продукта
- **Источник:** запрос владельца проекта от 2026-07-30
- **Приоритет:** обязательное

## Определения

**Проекция зависимости APM** — путь из `dependencies[*].deployed_files` в
`apm.lock.yaml` проекта-потребителя. Владельцем проекции считают пакет, в чьей
записи зависимостей указан этот путь.

**Проектный файл клиентского каталога** — файл в `.agents/`, `.claude/` или
`.codex/`, которого нет среди проекций зависимостей APM.

## Требование

Навык `ai-setup-apm` должен поставлять детерминированный валидатор, который
проект с APM и Git может включить в обязательные проверки. Валидатор читает
`apm.lock.yaml`, получает проекции зависимостей из фактической схемы файла
блокировки и сравнивает их с отслеживаемыми путями `git ls-files`.

Если Git отслеживает проекцию зависимости, валидатор завершается с ненулевым
кодом и для каждого нарушения выводит путь, пакет-владелец и указание удалить
файл из индекса Git и настроить `.gitignore`. Если нарушений нет, валидатор
завершается с кодом 0 и выводит краткое сообщение об успехе.

Валидатор не считает нарушением собственные исходные файлы `.apm/` проекта или
проектные файлы клиентских каталогов, если они не указаны в реестре
развёртывания зависимости. Он не изменяет `.gitignore`, индекс Git или рабочее
дерево, не использует модель, сеть или интерактивный ввод и не зависит от
ai-dev-team.

## Критерии приёмки

1. Поставляемый скрипт читает `apm.lock.yaml` и сопоставляет `deployed_files`
   зависимостей с NUL-разделённым выводом `git ls-files`.
2. Отслеживаемая проекция зависимости приводит к ошибке с путём, владельцем,
   указанием удалить файл из индекса и настроить `.gitignore`.
3. Неотслеживаемая проекция, собственный файл `.apm/` и проектный файл в
   клиентском каталоге не приводят к ошибке.
4. Несколько нарушений выводятся вместе с их правильными владельцами.
5. Отсутствие файла блокировки или репозитория Git даёт понятную диагностику
   без трассировки Python.
6. Имена путей с пробелами и не-ASCII символами сохраняются в проверке и
   диагностике.
7. Автоматические тесты валидатора входят в `apm run tests`.

## Подтверждение выполнения

- Валидатор поставляется как
  `.apm/skills/ai-setup-apm/scripts/validate-apm-git-boundary.py`.
- `tools/test-validate-apm-git-boundary.py` покрывает критерии приёмки в
  изолированных Git-репозиториях.
- Навык `ai-setup-apm` описывает назначение валидатора и его границы.
