# REQ-0022. Совместимость с VCS и политикой целевого проекта

## Требование

Политику работы с системой контроля версий (VCS) задаёт целевой проект.
Навыки продукта должны работать с любой VCS и установленной в проекте
политикой работы с ней. Навыки общего назначения должны сохранять полезный
основной результат также в проекте без VCS.

Процедуры, справки, шаблоны, скрипты и проверки навыка должны учитывать
фактически используемую VCS и применимые правила проекта. Они не должны
предполагать Git, наличие индекса, конкретный способ исключения файлов,
добавления изменений, фиксации или отправки и не должны подменять
политику проекта собственной. Явные указания пользователя и инструкции
более высокого приоритета сохраняют силу.

В частности, диагностический режим ограничивает предметные исправления,
но сам по себе не отменяет установленный проектом порядок работы с VCS,
включая обработку изменений, существовавших до начала задачи. При отсутствии
политики навык не выбирает её за пользователя. Неизвестные условия VCS
останавливают только зависимые действия и не мешают доступной диагностике.

Специализация для конкретной VCS допустима, если она явно ограничена своим
предметом или отдельной автоматизацией. Перед её применением проверяются
условия среды и полномочия. Такая специализация не должна становиться
обязательной для основного результата навыка общего назначения. Встроенная
проверка для Git не подтверждает защиту данных в другой VCS.

При выборе средств работы агент должен стремиться выполнить задачу наиболее
эффективным способом. Если доступная команда позволяет выполнить её эффективнее,
агент использует команду. Если команда недоступна, агент читает необходимые
материалы самостоятельно в пределах доступных средств и полномочий. Это правило
относится к любой VCS и не отменяет явно ограниченную специализацию инструмента.

## Область действия и связи

Требование распространяется на всё публикуемое содержимое `.apm/skills/**`.
Оно уточняет переносимость из [REQ-0007](REQ-0007.md) и
[REQ-0009](REQ-0009.md) и поддерживает назначение
[коллекции для разных проектов](../concept.md).

Специализированный валидатор границы APM и Git из
[REQ-0002](REQ-0002.md) сохраняется: его условия и предмет явно ограничены
APM и Git. Требование не отменяет защиту приватных данных или временное
хранение из [REQ-0021](REQ-0021.md). Их реализация должна учитывать VCS
целевого проекта.

## Критерии приёмки

1. Основной путь общего навыка не требует Git или его индекса. Проверочные
   случаи с другой VCS и без VCS получают полезный результат без настройки
   Git и без ложного обещания выполнить недоступную операцию.
2. В диагностике `ai-audit-agent-rules` при политике добавления всех изменений
   выполняется именно проектная политика. При политике добавления только
   изменений агента прежние изменения сохраняются. При ручном управлении
   индексом он остаётся без изменений. Предметные исправления во всех этих
   случаях требуют предусмотренного разрешения.
3. Настройка и сопровождение инструкций сохраняют существующую политику VCS.
   При её отсутствии выбор передаётся пользователю только для применимых
   действий. Проект с другой VCS или без VCS не получает правила индекса Git.
4. Для каждой зависимости от конкретной VCS в поставляемых материалах
   указаны условия применения и границы результата. Необязательная
   автоматизация при недоступности VCS оставляет основной результат общего
   навыка доступным.
5. Исключение локальных или приватных данных проверяется средствами фактической
   VCS либо данные размещаются вне её области. Отсутствие Git не принимается
   за отсутствие другой VCS или за доказательство защиты. При невозможности
   проверки ограничение явно названо, неподтверждённая защита не обещается.
6. Проверка охватывает инструкции, справки, шаблоны, скрипты и сценарии всей
   коллекции. Сценарии проверяют различающиеся политики и среды из пунктов
   1–5, а не только наличие слов «VCS» или «политика проекта».

## История изменений

- 2026-10-12 — требование принято.
  Проверка выявила нарушения в шести навыках. Реализация остаётся
  невыполненной, модельные проверки новых сценариев не проводились.

- 2026-10-13 — инструкции, справки, шаблоны, скрипты и сценарии переработаны.
  Подготовлены проверки разных политик и защита хранения с явными условиями
  VCS. Детерминированные проверки прошли. Модельное исполнение новых сценариев
  и реальная работа с другими VCS
  отдельно не проверялись.

- 2026-10-18 — владелец уточнил выбор средств для любой VCS: доступная
  команда, если она эффективнее, иначе самостоятельное чтение материалов.
