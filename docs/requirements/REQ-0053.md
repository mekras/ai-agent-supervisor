# REQ-0053. Расход контекста при подгрузке инструкций и разбор его скачков

## Статус и источник

Требование **принято** владельцем проекта 2026-11-20 ответом «REQ-0053:
принять как есть».
Классификация — `specification_change` по
[порядку изменений](../decisions/DR-0010.md#порядок-изменений).

Основание — разбор резкого скачка расхода лимита в сессии целевого проекта
с Claude Code 2.1.311 и проверочный опыт 2026-11-20.

- В основной сессии и двух её подагентах Claude Code трижды записал в кэш
  заново весь накопленный контекст: 286, 215 и 107 тыс. токенов. Каждый раз
  это происходило при первом обращении агента к файлу вложенного каталога,
  когда Claude Code за один шаг подгрузил 32–40 файлов инструкций: `CLAUDE.md`,
  `CLAUDE.local.md`, подключённые ими файлы и правила `.claude/rules/` без
  условия области. Подгрузки по 2–8 файлов в той же сессии кэш
  сохранили[^session].
- Опыт на тестовом проекте с той же версией показал, что подгрузка 16 файлов
  кэш сохраняет, а подгрузка 31 файла оставляет из кэша только начальную часть
  запроса. Отдельный Git-репозиторий, личный `CLAUDE.local.md`, вложенные
  навыки и определения подагентов сами по себе кэш не сбрасывали[^experiment].
- Кэш ищет совпадение не дальше 20 блоков назад от точки кэширования. Если
  после прежней записи добавилось больше блоков, совпадение не находится[^cache].
  Каждый подгруженный файл, по-видимому, становится отдельным блоком.
  Это объяснение согласуется с опытом, но устройство запроса Claude Code
  напрямую не проверено.
- Стоимость такой перезаписи растёт с длиной накопленного контекста. Файлы,
  загруженные при старте сессии, входят в первый запрос и потери кэша
  не вызывают.
- Подагенты той сессии запущены с настройками по умолчанию и работали
  на модели основной сессии. Политика подагентов проекта ссылалась
  на несуществующий пользовательский файл со схемой выбора моделей,
  а её входной фрагмент не был подключён ни к одной точке входа[^session].
- Разбор скачка назвал причиной файл инструкций, которого не было среди
  загруженных, не нашёл событие, сбросившее кэш, и адресовал все
  рекомендации человеку[^analysis].

Цель — продукт сам не допускает такой структуры инструкций и при разборе
расхода находит устранимую причину. Человеку не нужно разбираться в работе
кэша и подгрузке инструкций: проверку и исправление выполняет агент. Это
следует [назначению коллекции](../concept.md) и приоритету стоимости для
конечного пользователя при сохранении качества по [REQ-0003](REQ-0003.md).

## REQ-0053.1. Размер одновременной подгрузки инструкций в Claude Code

Когда агент настраивает, сопровождает или проверяет инструкции проекта,
который использует Claude Code, он находит каждое место, где Claude Code
подгружает инструкции по ходу работы. Это вложенный каталог с собственными
`CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md` или правилами
`.claude/rules/`, а также правила с условием `paths:`, которые становятся
применимыми при обращении к одному файлу. Для каждого места агент считает файлы, которые попадут в контекст
за одно обращение: файлы инструкций каталога, правила `.claude/rules/` этого
каталога без условия области, подходящие правила с условием и подключённые
ими файлы.

Если в одну подгрузку попадает больше 15 файлов, агент сообщает о риске.
При первом обращении к этому месту посреди сессии Claude Code может
записать в кэш заново весь накопленный контекст, и стоимость растёт
с длиной сессии. Предел взят с запасом ниже проверенных 16 файлов,
потому что в тот же шаг попадают и другие блоки запроса. Файлы, загружаемые
при старте сессии, в подсчёт не входят.

Исправление уменьшает число файлов в подгрузке без потери правил по
[REQ-0050](REQ-0050.md): объединяет безусловные правила одного места
по темам, переводит правила, нужные только для части файлов, под условие
`paths:` либо убирает из подгрузки файлы, адресованные не проекту, по
[REQ-0051](REQ-0051.md). Если правило развёрнуто пакетом, исправление
вносится в его исходник, а не в развёрнутую копию. После исправления агент
повторяет подсчёт. В режиме диагностики он показывает исправление,
не внося его.

## REQ-0053.2. Новое правило без превышения предела подгрузки

Когда агент создаёт новый файл правила для проекта, который использует
Claude Code, — при сопровождении инструкций, по итогам разбора нарушения
или при обучении на опыте, — он считает подгрузку места, где правило будет
загружаться, по REQ-0053.1. Если новый файл превысит предел, агент
добавляет правило в существующий файл того же места или ставит его под
условие `paths:` и сообщает об этом в итоге работы.

## REQ-0053.3. Разбор скачка расхода

Когда агент разбирает резкий рост расхода токенов или лимита по истории
сессий, он:

1. находит, на каких вызовах модели вырос расход, отдельно для основной
   сессии и каждого подагента,
2. для каждого вызова, где из кэша прочитана только начальная часть запроса,
   а начало истории не менялось, находит событие между этим и предыдущим
   вызовом: подгрузку инструкций и число её файлов, смену инструментов,
   модели или настроек, возобновление сессии, паузу дольше срока хранения
   кэша,
3. устанавливает загруженные файлы по записям журнала сессии, а не по
   файлам, найденным на диске,
4. для подагентов устанавливает фактическую модель и, если она взята
   по умолчанию, проверяет, доходит ли до рабочих сессий политика
   подагентов проекта,
5. формулирует каждую рекомендацию как изменение правил, настроек или
   структуры инструкций, которое выполнит агент, с названием владельца
   изменения и навыка. Человеку адресуется только действие, требующее его
   полномочий или доступа, например изменение в другом репозитории,
   с объяснением причины и готовым запросом.

## Критерии приёмки

1. **Крупная подгрузка при аудите** (REQ-0053.1). Вложенный каталог проекта
   с Claude Code содержит `CLAUDE.md`, `CLAUDE.local.md` и 29 правил без
   условия области. Находка аудита называет каталог, 31 файл, риск полной
   перезаписи кэша при первом обращении посреди сессии и исправление.
   Файлы проекта в режиме диагностики не меняются.
2. **Небольшая подгрузка** (REQ-0053.1). Вложенный каталог подгружает
   8 файлов. Аудит не создаёт находки о подгрузке.
3. **Правила из пакета** (REQ-0053.1). Крупную подгрузку образуют правила,
   развёрнутые APM из инструкций проекта. Исправление направлено в исходные
   инструкции, а не в развёрнутые копии, и повторный подсчёт выполнен после
   повторной развёртки.
4. **Новое правило у предела** (REQ-0053.2). Место уже подгружает 15 файлов,
   разбор нарушения предлагает новое правило для этого места. Агент
   добавляет правило в существующий файл того же места или под условие
   `paths:` и называет причину в итоге.
5. **Причина сброса кэша** (REQ-0053.3). Журнал показывает чтение из кэша
   только начальной части запроса сразу после подгрузки 32 файлов при
   неизменном начале истории. Разбор называет это событие, место и число
   файлов и не приписывает расход файлу, которого нет среди загруженных.
6. **Подагенты на модели по умолчанию** (REQ-0053.3). Подагенты работали
   на модели основной сессии, политика подагентов ссылается на
   несуществующий файл. Разбор называет неподключённую политику причиной
   и предлагает её восстановление через настройку подагентов.
7. **Адресат рекомендаций** (REQ-0053.3). Действия в пределах проекта
   и полномочий агента разбор не адресует человеку. Изменение в другом
   репозитории адресовано человеку вместе с готовым запросом.

## Связи и трассировка

Требование применяет проверку доставки правил из [REQ-0029](REQ-0029.md)
и [REQ-0033](REQ-0033.md) к стоимости подгрузки, а форму находки аудита
задают [REQ-0034](REQ-0034.md) и [REQ-0048](REQ-0048.md). Сохранность правил
при объединении задаёт [REQ-0050](REQ-0050.md), исключение правил пакетов
из подгрузки — [REQ-0051](REQ-0051.md). Решение сохраняет
[управление сложностью](REQ-0020.md): предел проверяется подсчётом файлов
без новой оснастки, а сведения о Claude Code остаются в справке о доставке
правил.

## Реализация и состояние проверки

Сведения о подгрузке, предел и способы исправления записаны в разделе
«Одновременная подгрузка инструкций»
[справки о доставке правил](../../.apm/skills/ai-audit-agent-rules/references/rule-delivery.md#одновременная-подгрузка-инструкций).
REQ-0053.1 при аудите реализовано в шаге 5 навыка `ai-audit-agent-rules`,
при сопровождении — в шаге 11 навыка `ai-agents-md-maintenance`. REQ-0053.2
реализовано в том же шаге 11 и в разделе справки о доставке правил. К разделу
направляют шаг 6 навыка `ai-rule-failure-analysis` и раздел «Выбор изменения»
[справки об обучении на опыте](../../.apm/skills/ai-skill-development/references/learning.md#выбор-изменения).
REQ-0053.3 реализовано в
[справке о скачке расхода](../../.apm/skills/ai-usage-analysis/references/cost-spike.md),
которую вызывает шаг 4 навыка `ai-usage-analysis`. Описание навыка
дополнено причинами скачков расхода, чтобы навык выбирался для такого
вопроса.

Критериям 1 и 2 соответствует сценарий
`ai-audit-agent-rules-result-claude-large-lazy-instruction-load`
в [проверочных случаях аудита](../../.apm/skills/ai-audit-agent-rules/evals/result-scenarios.json).
Критерию 3 соответствует сценарий
`ai-agents-md-maintenance-result-apm-rules-lazy-load-source`, критерию 4 —
`ai-agents-md-maintenance-result-new-rule-at-lazy-load-limit`
в [проверочных случаях сопровождения](../../.apm/skills/ai-agents-md-maintenance/evals/result-scenarios.json).
Критериям 5 и 7 соответствует сценарий
`ai-usage-analysis-result-cost-spike-lazy-load`, критериям 6 и 7 —
`ai-usage-analysis-result-subagents-default-model`
в [проверочных случаях анализа применения](../../.apm/skills/ai-usage-analysis/evals/result-scenarios.json).
Выбор навыка для вопроса о скачке расхода проверяет случай
`ai-usage-analysis-cost-spike` в его сценариях выбора.

Предел подтверждён только для Claude Code 2.1.311. При смене версии
агент подтверждает поведение наблюдением в проекте. Структурные проверки
сценариев не подтверждают исполнение правил моделью.
