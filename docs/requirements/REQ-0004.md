# REQ-0004: Пользовательское ядро политики выполнения

- **Статус требования:** принято 2026-08-04
- **Состояние реализации:** выполнено
- **Уровень:** функциональное требование продукта
- **Источник:** направление, согласованное владельцем проекта 2026-08-04
- **Приоритет:** обязательное

## Определения

**Политика выполнения** — набор правил, по которым для класса задач выбирают
маршрут выполнения, проверяют его пригодность и передают работу между этапами.
Политика не выполняет задачу и не заменяет внешний механизм запуска агента.

**Пользовательское ядро** — приватная настройка одного пользователя, общая для
его проектов. В ядре хранятся доступные среды выполнения, назначения моделей,
сведения о цене и лимитах, допущенные маршруты и свидетельства их
квалификации.

**Проектное уточнение** — настройка конкретного проекта, которая связывает
классы его задач с пользовательским ядром и добавляет критерии приёмки,
обязательные проверки, запреты и иные условия этого проекта.

**Действующая политика** — результат применения пользовательского ядра и
проектного уточнения для выбранной среды выполнения.

## Требование

Продукт должен поставлять настройку политики выполнения, которая отделяет
пользовательское ядро от проектных уточнений.

Настройка должна сохранять пользовательское ядро в приватном пользовательском
слое активной среды либо в ином локальном файле, который не попадает в Git без
отдельного решения пользователя. Точные идентификаторы моделей, цены, лимиты и
данные учётной записи должны оставаться в этом приватном слое. Публикуемые
навыки не должны содержать такие значения.

Проектное уточнение должно хранить только сведения, зависящие от проекта:
классы задач, критерии приёмки, обязательные свидетельства, проверки и запреты.
Оно не должно копировать из пользовательского ядра точные назначения моделей,
цены или правила, общие для всех проектов, если пользователь явно не решил
иначе.

При формировании действующей политики проектное уточнение может сужать область
допустимых маршрутов или усиливать критерии результата. Оно не может ослаблять
ограничение сохранения качества из [REQ-0003](REQ-0003.md) или выдать
неквалифицированный маршрут за квалифицированный.

Настройка должна показывать пользователю действующую политику, её источники и
неприменённые проектные уточнения. Она не должна создавать пользовательское
ядро или проектное уточнение молча.

## Область действия

Требование относится к будущему публичному навыку настройки политики
выполнения, его образцам, проверкам и устанавливаемым средствам.

Требование не включает реализацию постоянно работающего контроллера, сбор
истории сессий пользователя или автоматический выбор модели для уже запущенной
корневой сессии. Эти возможности принадлежат внешней интеграции с активной
средой выполнения.

## Критерии приёмки

1. Настройка создаёт или обновляет пользовательское ядро в приватном слое,
   который не добавляется в Git без отдельного решения пользователя.
2. Два проекта могут использовать одно пользовательское ядро и иметь разные
   проектные уточнения без копирования точных назначений моделей, цен и
   лимитов в настройку проектов.
3. Для каждого проекта настройка выводит действующую политику и указывает,
   какие правила пришли из пользовательского ядра, а какие из проектного
   уточнения.
4. Проектное уточнение, пытающееся ослабить обязательные критерии качества или
   применить неквалифицированный маршрут, отклоняется с понятной причиной.
5. Проверки продукта подтверждают, что в публикуемых файлах нет конкретных
   идентификаторов моделей, цен, лимитов, данных учётной записи и путей
   пользователя.
6. Если активная среда не предоставляет пользовательский слой настройки,
   продукт предлагает локальный неотслеживаемый файл и явно сообщает его
   расположение и способ исключения из Git.

## Подтверждение выполнения

Требование реализовано навыком
`ai-setup-execution-policy`. Он поставляет отдельные образцы пользовательского
ядра и проектного уточнения, показывает действующую политику с источниками и
отклоняет приватные поля либо ослабление обязательных свидетельств в проектном
файле. Детерминированная проверка охватывает разделение слоёв, защиту приватного
файла от Git и вывод неприменённого класса задач.
