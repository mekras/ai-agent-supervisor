# REQ-0033. Сохранение области и доставки инструкций при сопровождении

## Статус требования

Требование **принято** владельцем проекта 2026-10-18.

## Источник и назначение

Владелец проекта принял базовые правила 2026-10-18 в ходе перехода
на спецификацию как исходник.
Основание обязательств — это решение владельца. Прежняя реализация служит
свидетельством для сопоставления и не добавляет обязательств автоматически.
Требование поддерживает [назначение коллекции](../concept.md) и записано
по [порядку изменений DR-0010](../decisions/DR-0010.md#порядок-изменений).

## Требование

До изменения инструкций агент должен установить действующие входы и область
каждого изменяемого правила. Решения пользователя сохраняются. Конфликт уровней
инструкций показывается явно и не разрешается скрытой отменой общего правила.
Общие правила не дублируются между входами разных оснасток, если подтверждён
способ обратиться к одному источнику. Ссылки и способ доставки проверяются.

## Область действия и связи

Сопровождение инструкций через `ai-agents-md-maintenance`. Политика VCS
сохраняется по [REQ-0022](REQ-0022.md).

## Критерии приёмки

1. Для каждого изменённого правила известна область действия.
2. Локальное правило не отменяет общее скрыто, конфликт показан явно.
3. Ссылки и способ доставки общих правил проверены для действующих входов.

## Состояние проверки

Производные инструкции находятся в
[навыке ai-agents-md-maintenance](../../.apm/skills/ai-agents-md-maintenance/SKILL.md),
материалы проверок — в
[его сценариях](../../.apm/skills/ai-agents-md-maintenance/evals/result-scenarios.json).
Ссылки задают направление проверки, а не подтверждают полноту покрытия.

Фактическое исполнение критериев агентом и восстановление из канонического
описания не проверены. Структурные проверки не заменяют эти свидетельства.

## История изменений
