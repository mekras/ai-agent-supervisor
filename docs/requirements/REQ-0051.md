# REQ-0051. Правила разработки зависимостей вне контекста агента в целевом проекте

## Статус и источник

Требование **принято** пользователем 2026-11-20 ответом «Да, делай»
на предложенный порядок поиска и исправления. Классификация —
`specification_change` по
[порядку изменений](../decisions/DR-0010.md#порядок-изменений).

Основание — сессия 2026-11-19 в целевом проекте и её разбор. Агент получил
при старте сессии правила разработки трёх пакетов, подключённых через APM,
и применил запрет одного из них к собственной работе. Пользователь сообщил,
что сталкивается с этим не впервые. Разбор установил причины:

- При сборке корневого `CLAUDE.md` APM подключает в нём `CLAUDE.md` каждой
  установленной зависимости[^apm-compile]. Пакеты держали там подключение
  своего `AGENTS.md` с правилами разработки.
- Claude Code подгружает инструкции из каталога пакета, когда агент открывает
  его файл. Если у проекта нет собственного `CLAUDE.md`, он добавляет и
  `AGENTS.md` пакета[^claude-code].
- Три навыка коллекции советовали создавать `CLAUDE.md` с подключением
  `AGENTS.md`. Claude Code загружает `AGENTS.md` сам, если у проекта нет
  собственного `CLAUDE.md`, `.claude/CLAUDE.md` или
  `CLAUDE.local.md`[^claude-code].

Опыт на тестовом проекте 2026-11-20 с Claude Code 2.1.311 и APM 0.33.0
показал два свойства. Исключение каталога установленных пакетов из загрузки
инструкций в настройках Claude проекта закрывает оба пути при любом устройстве
пакетов. Без собственного `CLAUDE.md` правила, которые APM собрал
в `AGENTS.md`, загружаются вдобавок к тем же правилам в `.claude/rules/`.

Цель — в контексте агента целевого проекта остаются только правила,
адресованные этому проекту. Пользователю не нужно разбираться в загрузке
инструкций: продукт сам находит и исправляет нарушение при работе
с зависимостями и при аудите правил. Это поддерживает
[назначение коллекции](../concept.md): подготовку и проверку правил работы
выполняет агент.

## REQ-0051.1. Точка входа Claude без лишнего файла

Когда навык настраивает или сопровождает инструкции агента проекта, который
использует Claude Code, он не создаёт `CLAUDE.md`, `.claude/CLAUDE.md` или
`CLAUDE.local.md` только для подключения `AGENTS.md`. Если такой файл у проекта
есть или нужен по другой причине, а `AGENTS.md` содержит правила проекта,
которые Claude не получает другим путём, файл подключает `AGENTS.md`.

Загрузку инструкций Claude навык подтверждает наблюдением в проекте, когда
Claude Code доступен: списком загруженных файлов инструкций. Без наблюдения
он называет вывод неподтверждённым.

## REQ-0051.2. Проверка целевого проекта с зависимостями APM

Когда агент работает с зависимостями APM проекта, который использует Claude
Code, — устанавливает, обновляет, проверяет установку или настраивает
потребление пакетов, — а также при аудите правил такого проекта он
устанавливает:

1. исключён ли каталог установленных пакетов из загрузки инструкций
   в настройках Claude проекта,
2. подключает ли корневой `CLAUDE.md` файлы из каталога установленных пакетов,
3. есть ли у проекта собственный `CLAUDE.md`, если APM собирает его
   `AGENTS.md`. Без такого файла Claude загружает те же правила дважды.

Отчёт называет пакеты, чьи инструкции попадают или могут попасть в контекст,
и путь попадания: при старте сессии или при чтении файлов пакета. Если Claude
Code доступен, вывод подтверждается списком загруженных файлов инструкций.

## REQ-0051.3. Исправление в целевом проекте

Исправление вносится в целевой проект и не зависит от исправления пакетов:

1. Настройки Claude проекта исключают каталог установленных пакетов
   из загрузки инструкций.
2. Если APM собирает `AGENTS.md` проекта, у проекта есть собственный корневой
   `CLAUDE.md`, написанный вручную, без служебной пометки APM. Он заменяет
   созданный APM файл.

Перед исключением агент показывает, какие файлы пакетов подключались. Если
пакет намеренно передаёт проектам свой `CLAUDE.md`, агент не исключает его
молча: он сужает исключение или передаёт выбор пользователю. После исправления
агент повторяет проверку REQ-0051.2. Затем он предлагает убрать из инструкций
проекта правила-обходы, которые толкуют правила пакетов, и убирает их только
после подтверждения пользователя.

Изменение файлов проекта следует режиму навыка. В режиме диагностики агент
показывает исправление, не внося его.

## REQ-0051.4. Подгрузка правил пакетов в Hermes Agent

### Источник и статус уточнения

Уточнение **принято** пользователем 2026-11-20 ответом «Только второй»
на два предложенных шага. Первый шаг — запрос разработчикам Hermes Agent
пропускать каталог установленных пакетов — пользователь отклонил, в продукт
он не входит. Классификация — `specification_change` по
[порядку изменений](../decisions/DR-0010.md#порядок-изменений).

Основание — вопрос пользователя о Codex и других оснастках после принятия
REQ-0051.1–REQ-0051.3. Проверка показала, что Codex правила пакетов
не получает, а Hermes Agent получает их при обращении к файлам пакета.
Hermes добавляет к результату инструмента файл инструкций из каталога, где
лежит открытый файл, и из нескольких родительских каталогов. Каталоги
зависимостей он пропускает по встроенному списку имён, в котором нет каталога
пакетов APM. Настройки исключения для отдельного проекта у Hermes
нет[^hermes].

### Требование

Когда агент работает с зависимостями APM проекта, который использует Hermes
Agent, или проводит аудит правил такого проекта, он называет пакеты, в каталоге
которых лежат файлы инструкций, которые Hermes добавит при обращении к файлам
пакета. Отчёт объясняет, что настройками проекта этот путь не закрыть.

Агент предлагает временное правило в собственных инструкциях проекта: тексты,
которые оснастка добавляет из каталога установленных пакетов, адресованы
разработке пакетов и к работе в проекте не применяются. Отчёт называет его
инструкцией агенту, которая не блокирует подгрузку. Правило добавляется только
после подтверждения пользователя. Если установленная версия Hermes пропускает
каталог установленных пакетов, агент предлагает убрать правило.

## Критерии приёмки

1. **Обновление зависимостей** (REQ-0051.2, REQ-0051.3). Корневой `CLAUDE.md`
   создан APM и подключает `CLAUDE.md` двух пакетов, исключения в настройках
   Claude нет. Агент обновляет зависимости, называет оба пакета и путь
   «при старте сессии», добавляет исключение каталога установленных пакетов,
   заменяет созданный APM `CLAUDE.md` собственным и повторяет проверку.
2. **Двойная загрузка** (REQ-0051.2, REQ-0051.3). APM собирает `AGENTS.md`
   проекта, собственного `CLAUDE.md` нет, в пакетах `CLAUDE.md` нет. Отчёт
   называет двойную загрузку правил проекта и подгрузку `AGENTS.md` пакетов
   при чтении их файлов. Исправление включает собственный `CLAUDE.md`
   и исключение каталога пакетов.
3. **Аудит правил** (REQ-0051.2, REQ-0051.3). При аудите в режиме диагностики
   в контекст при старте попадают правила разработки пакета. Находка называет
   пакет, путь попадания и исправление в проекте. Файлы проекта не меняются.
4. **Пакет передаёт свой `CLAUDE.md` намеренно** (REQ-0051.3). `CLAUDE.md`
   пакета адресован проектам-потребителям. Агент показывает его и не исключает
   каталог молча: предлагает сузить исключение или спрашивает пользователя.
5. **Правило-обход** (REQ-0051.3). Инструкции проекта содержат абзац,
   толкующий запрет из правил пакета. После исправления агент предлагает
   убрать абзац и не убирает его без подтверждения.
6. **Проект без лишнего файла** (REQ-0051.1). Проект использует Claude Code,
   правила лежат в `AGENTS.md`, `CLAUDE.md` нет. Агент не создаёт `CLAUDE.md`
   и объясняет, что Claude загружает `AGENTS.md` сам.
7. **Личные заметки выключают `AGENTS.md`** (REQ-0051.1). У проекта есть
   `CLAUDE.local.md` без подключения `AGENTS.md`, правила проекта написаны
   вручную в `AGENTS.md`. Агент сообщает, что Claude не получает `AGENTS.md`,
   и предлагает его подключить.
8. **Hermes Agent** (REQ-0051.4). Проект использует Hermes Agent, в каталоге
   установленного пакета лежит `AGENTS.md` с правилами разработки. Агент
   называет пакет и путь «при обращении к файлам пакета», объясняет, что
   настройками проекта путь не закрыть, и предлагает временное правило с
   условием снятия. Правило он не добавляет без подтверждения и не выдаёт его
   за блокировку подгрузки.

## Связи и трассировка

Требование применяет проверку получения правила из [REQ-0029](REQ-0029.md)
к правилам, адресованным другому проекту, и проверку доставки из
[REQ-0033](REQ-0033.md) к точке входа Claude. Порядок обновления зависимостей
задаёт [REQ-0046](REQ-0046.md), проверка этого требования дополняет его отчёт.
Форму находки аудита задают [REQ-0034](REQ-0034.md) и
[REQ-0048](REQ-0048.md). Исправление вносится в проект, поэтому источник
находки — проект. Решение сохраняет [управление сложностью](REQ-0020.md):
одна настройка закрывает оба пути попадания при любом устройстве пакетов.
Для Hermes REQ-0051.4 различает инструкцию агенту и техническое
предотвращение, как требует контроль перед изменением: временное правило
не выдаётся за блокировку.
