# REQ-0051. Доставка правил проекта и границы применения правил зависимостей

Агенту должны быть доступны все правила, адресованные целевому проекту, без
дублирования в одном контексте. Правила разработки зависимостей не должны
применяться к работе в целевом проекте.

## REQ-0051.1. Доставка правил проекта

Результатом настройки и сопровождения инструкций должна быть доступность
всех применимых правил проекта с сохранением их согласованного содержания
и области действия. Вывод о доставке должен указывать, какие правила агент
фактически получил и в какой части доставка осталась неподтверждённой.

## REQ-0051.2. Проверка загрузки правил зависимостей

Результат проверки должен показывать, какие правила разработки зависимостей
попадают или могут попасть в контекст агента целевого проекта и какие правила
проекта он получает повторно.

Для каждой находки в результате должны быть указаны затронутые правила,
их источник, адресат и основание вывода. Возможная доставка должна быть
отличима от подтверждённой. Если свидетельств недостаточно, в результате
должно быть указано, что осталось неподтверждённым.

## REQ-0051.3. Исправление в целевом проекте

Если средства целевого проекта позволяют предотвратить загрузку правил
разработки зависимостей, разрешённое исправление должно прекратить их
загрузку без изменения зависимостей. Доступность правил проекта и правил,
предназначенных для потребителей зависимостей, должна сохраниться без
дублирования.

До правки пользователь должен получить сведения о том, какие правила она
затронет. Если способ сохранить нужные правила не установлен, агент должен
передать решение пользователю. При диагностике и при поручении только обновить
зависимости результат должен содержать находку и предложение исправления.
Изменения настроек и инструкций для устранения находки допустимы только
в пределах разрешения пользователя.

Результат исправления должен показывать, прекращена ли лишняя загрузка,
сохранились ли нужные правила и какие проблемы остались. Когда причина
обходной меры устранена, агент должен предложить её убрать. Если для этого
нужно изменить инструкции проекта, требуется согласие пользователя.

## REQ-0051.4. Ограничение применения загружаемых правил

Если средствами проекта нельзя предотвратить загрузку правил разработки
зависимостей, агент должен сообщить об ограничении и предложить меру, которая
снижает риск применения этих правил и сохраняет применимость правил для
потребителей. В результате должно быть указано, сохранится ли загрузка
правил и как мера повлияет на их применение. Изменять инструкции проекта
для этой меры можно только с согласия пользователя. Когда причина для
принятой меры отпадает, агент должен предложить её отменить.

## Критерии приёмки

1. **Обновление зависимостей** (REQ-0051.2, REQ-0051.3). При обнаружении
   проблемы названы затронутые зависимости. Если поручение ограничено
   обновлением, исправление только предложено. После разрешённого исправления
   подтверждены прекращение лишней загрузки и сохранение нужных правил.
2. **Дубли и правила разработки** (REQ-0051.2, REQ-0051.3). В результате различимы
   повторно получаемые правила проекта и правила разработки зависимостей.
   Для каждого вывода приведено основание. После разрешённого исправления
   правила разработки больше не загружаются там, где загрузку можно
   предотвратить, а нужные правила доходят без дублей.
3. **Аудит правил** (REQ-0051.2, REQ-0051.3). Для находки указаны правила,
   их источник, адресат, основание вывода и предлагаемое действие.
   Диагностика завершена без изменения предметных файлов.
4. **Правила для потребителей** (REQ-0051.3). Исправление сохраняет доступность
   правил, предназначенных для потребителей. Если сохранение не подтверждено,
   вопрос передан пользователю до затрагивающей эти правила правки.
5. **Отмена обходной меры** (REQ-0051.3). После подтверждённого устранения
   причины предложено отменить меру. Без согласия пользователя связанные
   с ней инструкции проекта сохранены.
6. **Полная доставка** (REQ-0051.1). Доступность всех применимых правил
   сохранена. В результате указано основание вывода о доставке.
7. **Неполная доставка** (REQ-0051.1). Недоступные правила указаны отдельно
   от правил, получение которых осталось неподтверждённым. После разрешённого
   исправления недостающие правила доступны. Согласованное содержание
   и область действия правил сохранены.
8. **Загрузку нельзя предотвратить** (REQ-0051.2, REQ-0051.4). В результате
   указано, какие правила разработки могут быть загружены и на чём основан
   вывод. Предложенная мера ограничивает применение этих правил и сохраняет
   применимость правил для потребителей. Названы эффект, сохраняющиеся
   ограничения и условие отмены. Мера внесена в инструкции проекта только
   с согласия пользователя. При устранении причины предложена отмена.
