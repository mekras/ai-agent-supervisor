# REQ-0007: Базовый переносимый маршрут навыка

- **Статус требования:** принято 2026-08-05
- **Состояние реализации:** выполнено
- **Уровень:** атрибут качества продукта
- **Источник:** решение владельца проекта от 2026-08-05
- **Приоритет:** обязательное

## Определения

**Базовый маршрут P0** — полезный основной результат навыка, который агент
может получить по инструкциям и возможностям целевой задачи без запуска
поставляемого скрипта, установки интерпретатора, загрузки пакета или наличия
POSIX-оболочки.

**Автоматизированный маршрут P1** — необязательное ускорение или проверка,
которым нужен явно объявленный переносимый интерпретатор или исполняемый файл.

**Платформенный маршрут P2** — необязательное действие, привязанное к явно
названной операционной системе, оболочке или оснастке.

## Требование

Каждый навык общего назначения должен иметь базовый маршрут P0. Отсутствие
Python, Node.js, POSIX-оболочки, сети или возможности установить пакет не должно
лишать пользователя всего полезного результата навыка.

Навык без P0 допустим только тогда, когда его предмет по своей природе зависит
от конкретной платформы или исполняемой среды. Такое ограничение должно быть
явно указано в поле `compatibility` и в процедуре навыка. Навык нельзя объявлять
переносимым за пределами этой среды.

## Критерии приёмки

1. У навыка со скриптами описан P0 либо обосновано обязательное ограничение
   среды.
2. P0 не требует запуска файла из `scripts/**`, установки пакета или доступа к
   сети.
3. Инструкция различает P0, P1 и P2 и не выдаёт платформенный маршрут за общий.
4. Проверка коллекции отклоняет новый навык со скриптами без объявления
   совместимости и базового маршрута.
5. Сценарий результата проверяет случай, когда Python и POSIX-оболочка
   недоступны.
6. Каждый публичный Python-скрипт P1 первого уровня в `scripts/` имеет
   исполнимый контракт с реалистичной фикстурой и хотя бы одним успешным
   рабочим сценарием. Ожидаемый отказ не заменяет успешный сценарий. Контракт
   запускает поставляемую команду и проверяет внешний результат. Команды из
   процедуры навыка сопоставлены со сценариями контракта. Для сохранённого JSON
   рабочий сценарий выполняет запись и повторно читает созданный файл. Каждая
   операция содержит `inputs` с условными входами или пустой массив как явный
   результат проверки кода. Отсутствие поля отклоняется. Успешный сценарий
   отклоняется, если проверяет действительно отсутствующий путь внутри
   фикстуры, покрываемая операция не объявляет этот путь в `inputs` и не создаёт
   либо не заменяет его как выход или состояние. Отрицательный результат
   проверки типа существующего файла или каталога не считается отсутствием.
7. Контроль качества публикуемой коллекции до и после остальных проверок
   отклоняет `__pycache__`, `.pyc` и `.pyo` в `.apm`, `.agents`, `.claude`,
   `.codex`, поставляемой оснастке и семантических путях `apm.lock.yaml`.
8. Для обычного Python-процесса процедура применяет наследуемую переменную
   `PYTHONDONTWRITEBYTECODE=1` либо ключ `-B` для одного подтверждённого
   процесса. Явные `py_compile` и `compileall` запрещены над защищёнными
   деревьями, потому что обе профилактические меры не останавливают компилятор.
9. Синтаксическая проверка Python читает исходник и компилирует его в памяти
   без импорта и записи байткода либо использует эквивалентный валидатор.
10. Самоприменение APM выполняет барьер до установки, после установки и после
    аудита. Если загрязнён файл блокировки, его пересоздают штатной установкой
    из чистого исходного дерева. Ручная правка lock-файла и разовое удаление
    кэша не считаются устранением причины.
