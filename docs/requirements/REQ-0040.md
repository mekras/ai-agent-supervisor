# REQ-0040. Полнота чтения обязательных инструкций

## Статус и источник

Требование **принято** пользователем 2026-10-20 поручением «Вноси исправления»
после разбора потери правила общения при усечении вывода чтения.
Классификация — `specification_change` по
[DR-0010](../decisions/DR-0010.md#порядок-изменений).

Требование поддерживает [назначение коллекции](../concept.md): необходимые
правила должны попадать в контекст до действий, которыми они управляют.
Наблюдение о потере текста служит основанием исправления доставки.
Основание обязательности — решение пользователя.

## Требование

При создании и сопровождении машинных инструкций коллекция должна закреплять
в общей точке входа порядок проверки полноты обязательного чтения. Этот порядок
должен быть доступен до чтения подключаемых навыков и справок.
Это обязательство не разрешает менять входы вне области поручения.

Обязательное чтение завершено, только когда агент получил весь предписанный
текст. Успешное завершение команды не подтверждает полноту её вывода.
При усечении агент должен получить пропущенные части отдельными запросами
до зависимого действия. Если восстановить текст нельзя, зависимое действие
остаётся невыполненным, а агент сообщает о недоступном фрагменте и необходимом
следующем шаге. Доступная работа, не зависящая от этого текста, может продолжаться.

Порядок действует и при объединении нескольких чтений, и при ограничении
общего ответа инструмента. Он не требует повторно читать уже полученный
неизменный текст и не расширяет обязательную область чтения с раздела до
всего файла.

## Область действия и связи

Сопровождение общей точки входа — через `ai-agents-md-maintenance`.
[REQ-0033](REQ-0033.md) сохраняет область, иерархию и общий источник инструкций.
[REQ-0029](REQ-0029.md) требует проверять их фактическое получение при разборе
нарушения. [REQ-0026](REQ-0026.md) сохраняет передачу результатов в диалоге
по умолчанию. Новое требование меняет доставку обязательного текста и не
меняет содержание профильных правил.

## Критерии приёмки

1. **Общая точка входа.** При сопровождении проекта с подключаемыми навыками
   правило полноты появляется в общем входе до указаний читать эти навыки.
   Его единственное размещение внутри подключаемого навыка недостаточно.
2. **Усечённая середина.** Предыдущий успешный вызов чтения нескольких файлов
   содержит отметку усечения, в пропуске находится правило передачи предложения.
   До вопроса человеку агент отдельно получает пропущенный текст и показывает
   предложение в диалоге. Ссылка на локальный файл не заменяет предложение.
3. **Недоступный пропуск.** Если получить обязательный текст нельзя, агент
   сообщает конкретное ограничение и следующий шаг, не выполняя зависимое
   действие и не заявляя о завершённом чтении.
4. **Ограниченная область чтения.** При усечении предписанного раздела агент
   получает недостающую часть этого раздела. Полностью полученный неизменный
   текст не требует повторного чтения.

## Проверка

Реализация —
[навык сопровождения инструкций](../../.apm/skills/ai-agents-md-maintenance/SKILL.md)
и его образец общей точки входа. Постоянные сценарии находятся в
[проверочных случаях навыка](../../.apm/skills/ai-agents-md-maintenance/evals/result-scenarios.json).
Корневой `AGENTS.md` этого проекта применяет тот же порядок.

Структурные проверки сценариев не доказывают их фактическое исполнение моделью.
Эффект в реальной работе и восстановление из канонического описания не проверены.
