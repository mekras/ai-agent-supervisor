# REQ-0048. Краткий отчёт аудита правил

## Статус и источник

Требование **принято** пользователем 2026-11-19 поручением исправить навык,
который породил перегруженный отчёт аудита правил. Классификация —
`specification_change` по
[порядку изменений](../decisions/DR-0010.md#порядок-изменений).

Основание — реальный отчёт аудита правил проекта для агентов. Разделы
«Проверенные объекты» и «Не проверено и почему» стояли до находок
и занимали значительную часть ответа. Пользователь оценил их как шум, который
мешает найти нужные сведения, и указал, что проверенное и непроверенное
достаточно показать максимум очень короткой сводкой. Форму с этими разделами
задавал только сам навык, принятым требованием она не была.

Требование поддерживает [назначение коллекции](../concept.md): человек
получает из аудита сведения для решения, не разбирая отчёт о ходе проверки.

## Требование

Отчёт аудита правил через `ai-audit-agent-rules` начинается с общего вывода
и находок. Содержание каждой находки задаёт [REQ-0034](REQ-0034.md).

Сведения об охвате отчёт даёт сводкой в одно-два предложения. Сводка называет
проверенное, непроверенную часть, которая ограничивает выводы, со способом её
проверить и источник, прочитанный сверх запроса ради конкретного вопроса.
Отчёт не перечисляет проверенные объекты с предметом проверки, использованными
навыками и итогом по каждому. Эти сведения и подтверждения без находок
остаются в следе работы. Подробный перечень охвата отчёт даёт по прямому
запросу пользователя.

## Критерии приёмки

1. **Отчёт начинается с результата.** Аудит правил находит один смысловой
   дубль. Отчёт начинается с общего вывода и находки. Сведения об охвате
   занимают не больше двух предложений. Перечня объектов со строками
   «Проверено на», «Использованы» и «Итог» нет.
2. **Ограничивающий пробел виден.** Правило ссылается на инструкции, которые
   недоступны в среде проверки. Сводка называет непроверенный вопрос и способ
   его проверить. Отчёт не утверждает, что конфликтов нет.
3. **Подробности по запросу.** Пользователь прямо просит перечислить всё
   проверенное по каждому файлу. Отчёт даёт такой перечень.
4. **Расширение охвата.** Для проверки конфликта аудит читает связанное
   правило сверх запроса. Сводка называет этот источник и вопрос, ради которого
   он прочитан.

## REQ-0048.1. Проблемы во внешних источниках

### Источник и статус уточнения

Уточнение **принято** пользователем 2026-11-20 ответом «Подтверждаю обе»
на предложенную дельту. Классификация — `specification_change` по
[порядку изменений](../decisions/DR-0010.md#порядок-изменений).

Основание — аудит правил этого проекта 2026-11-19 и работа по его находкам.
У трёх из семи находок источник лежал вне проекта: в плагине оснастки и
в пакете зависимости. Отчёт показывал их в общем списке наравне с проектными.
Это путало при исправлении и привело к ошибке: правку для одной из них внесли
в репозиторий пакета без поручения. Пользователь предложил перечислять такие
проблемы отдельно и явно указывать их источник, потому что умолчание о них
тоже было бы ошибкой.

### Требование

Для каждой находки аудит устанавливает её источник: артефакт, изменение
которого устраняет причину, и способ его изменить. Источник устанавливается
наблюдением, например по записи о развёртывании файла пакетом, по
происхождению текста, внедрённого хуком, или по расположению файла вне
проверяемого проекта. Файл проекта, который не развёрнут пакетом или другим
внешним механизмом, относится к проекту.

Находки с источником в проверяемом проекте отчёт показывает основным списком.
Остальные он показывает отдельным разделом после основного списка,
сгруппированными по источнику. Для каждого источника раздел называет, что это
за источник (пакет и его версия, плагин, пользовательская настройка или
оснастка), каким способом он меняется и как проблема проявляется в проекте.
Действием для такой находки отчёт называет изменение через этот способ:
запрос владельцу, команду или настройку. Находку с неустановленным источником
отчёт показывает в этом же разделе с пометкой и способом установить источник.

Общий вывод сообщает, сколько проблем исправляется в проекте и сколько вне
его. Если внешних проблем нет, раздела нет.

### Критерии приёмки REQ-0048.1

5. **Зависимость.** Правило из файла, развёрнутого пакетом по записи
   в блокировке, противоречит `AGENTS.md`. Находка стоит в разделе внешних
   источников, называет пакет и его версию, а действием предлагает запрос
   владельцу пакета. Отчёт не предлагает править развёрнутую копию.
6. **Смешанный отчёт.** В проекте две проблемы, в пакете одна. Основной список
   содержит две находки, раздел внешних источников — одну. Общий вывод
   разделяет их.
7. **Источник не установлен.** Файл правил проекта помечен как созданный
   внешним генератором, но ни записи о развёртывании, ни настройки генератора
   в проекте нет. Находка стоит в разделе внешних источников с пометкой
   и способом установить источник.
8. **Внешних проблем нет.** Все находки относятся к проекту. Раздела внешних
   источников в отчёте нет.

## Связи и трассировка

Требование задаёт форму отчёта для диагностики по [REQ-0034](REQ-0034.md)
и применяет к аудиту правил разделение фактов и сообщения из
[REQ-0052.7. Ответственность за содержание и подачу](REQ-0052.md#req-00527-ответственность-за-содержание-и-подачу):
навык аудита задаёт факты и действия, а отбор сведений для человека выполняет
`ai-human-communication`. Ограничения выводов сохраняются по
[REQ-0025](REQ-0025.md), обозначение способа проверки — по
[REQ-0024](REQ-0024.md).

Уточнение REQ-0048.1 задаёт место в отчёте для находок о тексте, внедрённом
хуками и плагинами, по [REQ-0034.1](REQ-0034.md#req-00341-текст-внедрённый-хуками-и-плагинами).
Границу исправления таких находок задаёт
[REQ-0034.2](REQ-0034.md#req-00342-граница-исправления-внешних-источников).

## Реализация и состояние проверки

Правило реализовано в разделе «Вывод»
[навыка ai-audit-agent-rules](../../.apm/skills/ai-audit-agent-rules/SKILL.md)
и разделе «Формат вывода»
[списка проверок](../../.apm/skills/ai-audit-agent-rules/references/audit-checklist.md).
Критерию 1 соответствует сценарий
`ai-audit-agent-rules-result-brief-coverage-summary`, критерию 2 —
`ai-audit-agent-rules-result-coverage-gap-limits-conclusion`, критерию 3 —
`ai-audit-agent-rules-result-detailed-coverage-on-request`, критерию 4 —
`ai-audit-agent-rules-result-related-source-for-conflict`
в [проверочных случаях](../../.apm/skills/ai-audit-agent-rules/evals/result-scenarios.json).

Уточнение REQ-0048.1 реализовано шагом 5а и разделом «Вывод» навыка, а также
разделом «Формат вывода» списка проверок. Критериям 5 и 6 соответствует
сценарий `ai-audit-agent-rules-result-external-sources-section`, критерию 7 —
`ai-audit-agent-rules-result-unknown-problem-source`, критерию 8 —
`ai-audit-agent-rules-result-brief-coverage-summary`.

Структурные проверки сценариев не подтверждают исполнение правила моделью.
Модельный прогон сценариев не выполнялся.
