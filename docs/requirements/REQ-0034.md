# REQ-0034. Диагностика действующих правил без предметных исправлений

## Статус требования

Требование **принято** владельцем проекта 2026-10-18.

## Источник и назначение

Владелец проекта принял базовые правила 2026-10-18 в ходе перехода
на спецификацию как исходник.
Основание обязательств — это решение владельца. Прежняя реализация служит
свидетельством для сопоставления и не добавляет обязательств автоматически.
Требование поддерживает [назначение коллекции](../concept.md) и записано
по [порядку изменений DR-0010](../decisions/DR-0010.md#порядок-изменений).

## Требование

Запрос проверки без разрешения предметных исправлений должен давать диагностику.
Действующее правило определяется по доставке и применимости. Каждая существенная
находка содержит текущее место, основание и следующее действие. Находки сверяются
с актуальным текстом. Диагностика сама по себе не разрешает предметные изменения.

## Область действия и связи

Проверка правил через `ai-audit-agent-rules`. Политика VCS остаётся отдельным
условием по [REQ-0022](REQ-0022.md), включая обработку ранее существовавших
изменений, если этого требует целевой проект.

## Критерии приёмки

1. Историческая заметка не принята за действующее правило без основания доставки и применимости.
2. Без разрешения предметных исправлений предметные файлы сохранены.
3. Существенные находки сверены с актуальным текстом и содержат место, основание и следующее действие.

## Состояние проверки

Производные инструкции находятся в
[навыке ai-audit-agent-rules](../../.apm/skills/ai-audit-agent-rules/SKILL.md),
материалы проверок — в
[его сценариях](../../.apm/skills/ai-audit-agent-rules/evals/result-scenarios.json).
Ссылки задают направление проверки, а не подтверждают полноту покрытия.

Фактическое исполнение критериев агентом и восстановление из канонического
описания не проверены. Структурные проверки не заменяют эти свидетельства.
