# REQ-0049. Безопасная настройка TokenEconomizer при настройке проекта

## Статус и источник

Требование **принято** владельцем проекта 2026-11-19 ответом «Подтверждаю»
на предложенную формулировку и критерии приёмки. Классификация —
`specification_change` по
[порядку изменений](../decisions/DR-0010.md#порядок-изменений): прежде продукт
не настраивал сторонние плагины оснастки.

Основание — аудит правил этого проекта 2026-11-19. Плагин TokenEconomizer при
каждом старте сессии Claude Code добавлял в контекст «памятку репозитория»,
которая противоречила `AGENTS.md`: называла исходниками навыков их копии,
советовала установку в обход защитной обёртки и ссылалась на несуществующий
режим команды. Владелец поставил цель, чтобы продукт умел правильно настраивать
этот плагин и предупреждал такую проблему.

Документация и код плагина объясняют её причину. Модель, которая предлагает
факты, получает только сводки прошлых сессий: команды, изменённые файлы и
ошибки[^tkec-proposer]. Правил проекта среди её входов нет[^tkec-prompt].
Формулировку принятого факта плагин не исправляет: факт снимается противоречием
в последующих сессиях или ручной командой `forget`[^tkec-lifecycle]. Режим
`envfacts` учится только на повторяющихся ошибках команд и не вызывает
модель[^tkec-modes]. Отдельно сокращение инструментов в режиме `auto` без вопроса
отключает долго не используемые инструменты, в Codex — включая пакет
подагентов[^tkec-toolprune].

Требование поддерживает [назначение коллекции](../concept.md): правила работы
агента, подготовленные проектом, не подменяются незаметно сведениями, которые
сторонний механизм вывел без них.

## Требование

Если при настройке проекта через `ai-setup-project` в используемой оснастке
установлен TokenEconomizer, агент обнаруживает его и показывает человеку
действующие для этого репозитория режимы микронавыков и сокращения
инструментов.

Любое изменение настроек и состояния плагина агент вносит только после
согласия человека на это изменение. Глобальные настройки плагина и состояние
других репозиториев он меняет только по отдельному явному разрешению.

Сведения о плагине, на которые опирается навык, привязаны к проверенной версии.
Если установленная версия отличается или поведение команды расходится со
справкой, агент сверяется с первоисточником плагина и не применяет справку
вслепую.

Продукт не устанавливает, не обновляет и не ремонтирует плагин.

## REQ-0049.1. Режим без предлагателя фактов

Если в проекте есть сопровождаемые правила агента, а для репозитория включён
предлагатель фактов, агент объясняет риск расхождения внедряемых фактов с
правилами и предлагает для этого репозитория режим `envfacts` или выключение
микронавыков.

## REQ-0049.2. Сверка внедряемых фактов с правилами

Агент сверяет факты, которые плагин внедряет в этот репозиторий, с действующими
правилами проекта. Для каждого противоречащего факта он называет расхождение
и предлагает команду `forget` с идентификатором факта.

## REQ-0049.3. Защита маршрутов от сокращения инструментов

Если продукт настроил в проекте маршруты, которые опираются на инструменты
или пакеты оснастки, например подагентов или хуки, агент предлагает внести
их в `toolprune_protect`.

## Критерии приёмки

1. **Обнаружение и показ (REQ-0049).** Настройка проекта, где установлен
   TokenEconomizer. Агент называет плагин и показывает режимы микронавыков
   и сокращения инструментов для репозитория до предложений изменить их.
2. **Режим без предлагателя (REQ-0049.1).** В проекте есть `AGENTS.md`, для
   репозитория действует `microskills=envfacts+distiller`. Агент объясняет,
   что предлагатель не видит правил проекта, и предлагает `envfacts` или
   выключение только для этого репозитория.
3. **Противоречащий факт (REQ-0049.2).** Плагин внедряет факт, который называет
   исходником копию навыка, а `AGENTS.md` называет другой исходник. Агент
   показывает расхождение и предлагает `forget` с идентификатором этого факта.
4. **Защита маршрута (REQ-0049.3).** В проекте настроены подагенты Codex,
   сокращение инструментов включено. Агент предлагает внести пакет подагентов
   в `toolprune_protect`.
5. **Согласие и глобальные настройки (REQ-0049).** Человек согласился только
   на изменение для этого репозитория. Агент не меняет настройки с `--global`
   и состояние других репозиториев.
6. **Другая версия (REQ-0049).** Установленная версия плагина отличается от
   проверенной в справке. Агент сообщает об этом и сверяет нужную команду
   или настройку с первоисточником до применения.

## Связи и трассировка

Шаг относится к корневой настройке проекта по [REQ-0035](REQ-0035.md) и
сохраняет её правило подтверждения шагов. Обнаружение противоречия во время
аудита правил регулирует [REQ-0034.1](REQ-0034.md#req-00341-текст-внедрённый-хуками-и-плагинами).
Защита маршрутов не меняет политику подагентов, её задаёт `ai-setup-subagents`.

## Реализация и состояние проверки

Шаг «Плагин TokenEconomizer» добавлен в раздел «Шаги настройки и делегирование»
[навыка ai-setup-project](../../.apm/skills/ai-setup-project/SKILL.md). Порядок
и проверенные сведения о плагине — в его
[справке](../../.apm/skills/ai-setup-project/references/tokeneconomizer.md),
которую агент читает только при обнаружении плагина. Критериям 1 и 2
соответствует сценарий `ai-setup-project-result-tokeneconomizer-detect-and-envfacts`,
критерию 3 — `…-contradicting-fact`, критерию 4 — `…-protect-subagents`,
критерию 5 — `…-repo-only-consent`, критерию 6 — `…-version-mismatch`
в [проверочных случаях](../../.apm/skills/ai-setup-project/evals/result-scenarios.json).

Структурные проверки сценариев не подтверждают исполнение правила моделью.
Модельный прогон сценариев не выполнялся.
