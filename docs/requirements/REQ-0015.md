# REQ-0015. Условия запуска обучения на опыте

## Требование

У пользователя должна быть возможность запускать обучение вручную и включать
автоматический запуск. По умолчанию обучение запускается вручную для текущего
проекта, пользователь может выбрать другую доступную область.

Во включённом режиме текущий агент перед итоговым ответом должен разбирать
новый опыт: повторяемый способ работы, решение ошибки, поправку пользователя
или недостаток навыка. Неизменившиеся наблюдения,
отклонённые предложения и записи самого обучения не должны вызывать повторный
разбор без новых оснований или запроса пользователя.

## Критерии приёмки

1. Ручной запуск работает по переданным материалам или доступной истории
   без внешней интеграции согласно [REQ-0007](REQ-0007.md).
2. Автоматический запуск можно включить и выключить. Во включённом режиме
   каждый перечисленный вид нового опыта вызывает разбор текущим агентом до
   итогового ответа.
3. Повторное получение прежних сведений не запускает обучение заново.
   При недоступности сохранения пользователь видит ограничение и сохраняет
   возможность разового разбора.

## REQ-0015.1. Проверка включения автоматического режима без чтения журнала

### Источник и статус уточнения

Уточнение **принято** владельцем проекта 2026-11-19 ответом «Да, делай»
на предложенную редакцию. Подготовка начата по его ответу «Да»
на предложение исправить постоянную строку подключения обучения в навыке
развития навыков. Классификация — `specification_change` по
[порядку изменений DR-0010](../decisions/DR-0010.md#порядок-изменений):
форма этой строки в требованиях не была закреплена.

Основание — аудит правил этого проекта 2026-11-19. Строка подключения в его
`AGENTS.md` требовала перед каждым итоговым ответом прочитать файл состояния
обучения. Вместе с правилом полноты обязательного чтения из
[REQ-0040](REQ-0040.md) это означало чтение всего файла размером около
230 КБ, хотя решение зависит от одного признака. Иначе агент нарушал одно
из двух правил. Справка обучения навыка `ai-skill-development` требует
добавить в инструкции проекта строку, по которой агент прочитает состояние,
но не ограничивает это чтение. Проектная строка уже исправлена и проверена
на фактическом файле. Контекст агента — ограниченный ресурс, и в него следует
отбирать сведения, нужные для результата[^aeng].

Цель — пользователь, включивший автоматическое обучение, не расходует контекст
на чтение растущего журнала наблюдений в каждой задаче и получает правило,
совместимое с полнотой обязательного чтения. Это поддерживает
[REQ-0014](REQ-0014.md) о минимальной стоимости контекста.

### Требование

Когда навык развития навыков добавляет в инструкции проекта постоянную строку
подключения автоматического обучения, строка должна:

1. Предписывать перед итоговым ответом проверить только признак включения
   автоматического режима (`learning.automatic`) и явно исключать для этой
   проверки чтение остального содержимого состояния. Ограничение не сужает
   чтение, которое нужно самому разбору опыта.
2. Называть способ проверки, который агент при настройке выполнил в среде
   проекта на фактическом файле состояния и получил значение признака.
   Если такого способа нет, строка ограничивает предписанное чтение разделом
   настройки обучения (`learning`).
3. Считать отсутствие файла состояния, раздела настройки обучения или признака
   включения ручным режимом, как задано в
   [договоре состояния обучения](tooling-interfaces.md#настройка-и-отбор-обучения).
   Ошибку чтения существующего файла строка не выдаёт за выключенный режим:
   агент не запускает автоматический разбор и сообщает об ошибке в итоговом
   ответе.

Если в инструкциях уже есть строка подключения, которая требует читать
состояние целиком, повторная настройка обучения заменяет её строкой по этому
требованию и не добавляет вторую.

Способ проверки выбирается по среде проекта, поэтому навык не закрепляет одну
оболочку или интерпретатор и сохраняет [REQ-0009](REQ-0009.md). Формат
состояния, условия запуска разбора и границы изменений по
[REQ-0016](REQ-0016.md) не меняются.

### Критерии приёмки REQ-0015.1

1. **Проверка признака.** Пользователь поручает включить автоматическое
   обучение в проекте, где доступна команда для чтения поля JSON.
   Добавленная строка предписывает проверить только признак включения,
   называет команду, которая при настройке вернула его значение
   на фактическом файле, и не требует читать файл состояния.
2. **Нет средства проверки.** В среде проекта нет подходящей команды.
   Строка ограничивает предписанное чтение разделом настройки обучения
   и не требует читать файл целиком.
3. **Нет состояния.** Файл состояния или признак включения отсутствует.
   Строка трактует это как ручной режим. Если файл есть, но не читается,
   строка требует сообщить об ошибке и не запускать автоматический разбор.
4. **Прежняя строка.** В инструкциях проекта есть строка, требующая прочитать
   состояние. Повторная настройка заменяет её, в инструкциях остаётся одна
   строка подключения.

### Реализация и состояние проверки REQ-0015.1

Правило реализовано в разделе «Разовая настройка и постоянная интеграция»
[справки обучения](../../.apm/skills/ai-skill-development/references/learning.md).
Критериям 1 и 3 соответствует сценарий
`ai-skill-development-result-learning-setup-proposals`, критерию 2 —
`ai-skill-development-result-learning-setup-no-json-command`, критерию 4 —
`ai-skill-development-result-learning-setup-replace-full-read-line`
в [проверочных случаях навыка](../../.apm/skills/ai-skill-development/evals/result-scenarios.json).
Корневой `AGENTS.md` этого проекта применяет ту же проверку.

Структурные проверки сценариев не подтверждают исполнение правила моделью.
Модельный прогон сценариев не выполнялся.
