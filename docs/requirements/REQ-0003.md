# REQ-0003: Сохранение качества при сокращении расхода моделей

- **Статус требования:** принято 2026-08-04
- **Состояние реализации:** не выполнено
- **Уровень:** ограничение продукта
- **Источник:** решение владельца проекта от 2026-08-04
- **Приоритет:** обязательное

## Определения

**Механизм сокращения расхода** — поведение публикуемого продукта, которое
уменьшает ожидаемый расход токенов, кредитов или лимита модели. К таким
механизмам относятся выбор модели, маршрутизация, передача работы между
моделями, сжатие контекста, ограничение вызовов инструментов и иные способы
исключить непроизводительные модельные ходы.

**Эталонный маршрут** — маршрут выполнения задачи, выбранный по требованиям к
результату, риску и необходимым свидетельствам без ограничения расходов.

**Сопоставимое качество** — выполнение для класса задач тех же критериев
приёмки и требований к свидетельствам, что и эталонный маршрут. Результат не
считается сопоставимым, если для выполнения тех же критериев его приходится
повторно выполнять на более сильной модели.

## Требование

Публикуемый продукт должен применять механизм сокращения расхода автоматически
только для класса задач, где до применения подтверждено сопоставимое качество
по сравнению с эталонным маршрутом.

Прогноз исчерпания бюджета, уже достигнутый расход или иной показатель цены не
должен понижать требования к результату или состав обязательных свидетельств.
Такой показатель не должен автоматически заменять выбранный для класса задач
маршрут на более дешёвый без подтверждения сопоставимого качества. Если задача
не укладывается в доступный бюджет при сохранении качества, продукт должен
сообщить пользователю о конфликте бюджета и качества. Он не должен неявно
заменять маршрут на более дешёвый с меньшей способностью выполнить задачу.

Если экономичный маршрут не получил свидетельств, обязательных для результата,
продукт должен передать работу маршруту, достаточному для выполнения требований,
сохранив проверяемые результаты уже выполненных шагов. Экономия не считается
достигнутой, если передача приводит к повторному выполнению задачи из-за
недостаточного качества предыдущего маршрута.

## Область действия

Требование распространяется на публикуемые навыки, сценарии маршрутизации,
правила выбора моделей, поставляемые средства запуска и отчёты, если они
настраивают, рекомендуют, применяют или оценивают сокращение расхода модели.

Требование не запрещает:

- сокращать дублирующийся контекст, ожидания, вызовы инструментов и другие
  непроизводительные ходы, если критерии результата остаются теми же.
- выбирать менее ресурсоёмкую модель для класса задач с подтверждённым
  сопоставимым качеством.
- явно показывать пользователю варианты, различающиеся по цене и качеству,
  без автоматического выбора более дешёвого варианта.
- ограничивать запуск задачи, если бюджет недостаточен для маршрута, который
  сохраняет требуемое качество.

## Критерии приёмки

1. Для каждого автоматически применяемого механизма сокращения расхода
   определены класс задач, эталонный маршрут, одинаковые критерии приёмки и
   обязательные свидетельства результата.
2. Результаты проверки механизма показывают, что он проходит те же критерии
   приёмки, что и эталонный маршрут. Если механизм не проходит хотя бы один из
   них, он не применяется автоматически для этого класса задач.
3. Механизм не понижает состав проверок или требования к свидетельствам из-за
   прогноза расхода, состояния лимита или цены модели. Он не заменяет маршрут
   на более дешёвый без подтверждения сопоставимого качества.
4. При недостаточном бюджете продукт сообщает о конфликте бюджета и качества и
   не выдаёт более дешёвый маршрут за равноценный.
5. При эскалации маршрута отчёт содержит причину эскалации, сохранённые
   свидетельства предыдущих шагов и фактическую модель выполнения. Если работу
   пришлось начать заново, отчёт прямо указывает, что экономия не подтверждена.
6. Сценарии результата покрывают как успешное применение экономичного маршрута,
   так и случай, когда он должен эскалироваться без выдачи неполного результата
   за готовый.

## Подтверждение выполнения

Требование не выполнено. Подтверждение потребует сценариев сравнения с
эталонным маршрутом, проверки фактического выбора модели и отчёта об
эскалациях.

## История изменений

  понижать качество результата.
