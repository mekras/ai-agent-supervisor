# DR-0003: Инструктивное ядро и необязательная автоматизация навыков

**Статус:** Принято 2026-08-05

## Контекст

Поставляемые навыки могут содержать Python- и POSIX-скрипты. В среде без
интерпретатора, пакета, сети или совместимой оболочки такой скрипт не работает,
хотя смысловая часть задачи часто выполнима самим агентом. Неявная зависимость
делает заявленную переносимость непроверяемой и способна заблокировать весь
навык из-за необязательного ускорения.

Решение затрагивает требования REQ-0007–REQ-0010, публичный договор навыков и
будущую структуру всех поставляемых скриптов. Отмена потребует миграции навыков,
проверок и пользовательских ожиданий, поэтому краткой заметки в плане
недостаточно.

## Рассмотренные варианты

1. Запретить любые скрипты. Вариант максимально прост для переноса, но ухудшает
   качество и стоимость повторяемых детерминированных операций.
2. Выбрать Python обязательной средой всей коллекции. Вариант упрощает
   автоматизацию, но исключает системы без Python и делает интерпретатор частью
   основного договора продукта.
3. Сохранить инструктивное ядро и разделить маршруты на P0, P1 и P2. Вариант
   требует явной классификации и проверок, зато сохраняет полезность без
   дополнительной среды и допускает автоматизацию там, где она оправдана.
4. Разрешить произвольные скрипты с предупреждением. Вариант почти не требует
   миграции, но не предотвращает скрытые зависимости и повторение проблемы.

## Решение

Принят вариант 3.

Каждый общий навык сохраняет P0 на инструкциях агента. Скрипты служат
необязательными ускорителями или детерминированными проверками P1 и P2. Перед их
запуском проверяются зависимости. При недоступности автоматизации навык
продолжает P0 и честно сообщает, какая проверка не выполнена.

POSIX запрещён не вообще, а в обязательном переносимом маршруте. Платформенный
скрипт разрешён в P2 с явной областью совместимости. Python-скрипты публикуемой
коллекции по умолчанию ограничены стандартной библиотекой. Сторонняя
зависимость требует отдельного обоснованного исключения и не может стать
единственным путём к результату общего навыка.

Поддерживаемая базовая матрица включает Codex и Claude Code на Linux, macOS и в
официальных режимах Windows в пределах файловых и инструментальных
возможностей агента. Автоматизированная матрица проверяется отдельно для
объявленного интерпретатора. Наличие Python не является условием применения
P0.

## Последствия

- Поле `compatibility` и процедура навыка должны раскрывать ограничения
  поставляемой автоматизации.
- Навык разработки навыков обязан классифицировать каждый скрипт и определить
  поведение без среды выполнения.
- Коллекция получает статический валидатор переносимости и негативный сценарий
  результата.
- Существующие навыки со скриптами получают явный P0 и предварительную проверку
  среды.
- Инструменты разработки репозитория могут требовать Python как P1, но это не
  превращает Python в зависимость установленного инструктивного ядра.

## Проверка и условия пересмотра

Решение проверяется требованиями REQ-0007–REQ-0010, валидатором импортов и
метаданных, сценариями отсутствующей среды и прогонами на заявленных
операционных системах.

Решение следует пересмотреть, если стандарт навыков введёт переносимый
универсальный рантайм или декларативный формат зависимостей, который одинаково
поддерживают целевые агенты.
