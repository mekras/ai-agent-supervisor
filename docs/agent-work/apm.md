# Работа с APM в этом репозитории

Это инструкции для агента в этом проекте. `AGENTS.md` направляет сюда перед
запуском `ait-setup`, установкой, обновлением или аудитом пакетов APM и
проверкой установки коллекции. Пути указаны от корня проекта.

## Аудит при настройке

При запуске `ait-setup` в этом репозитории вместо прямого `apm audit --ci`
используй `python3 tools/apm-audit-ci`. Команда сохраняет все проверки APM и
принимает только подтверждённое локальное переопределение исходника `.apm` над
той же транзитивной версией пакета.

## Установка

Проверку установки выполняй в отдельном тестовом проекте с кандидатом пакета
без зависимостей среды разработки. Если задача требует установки в рабочем
проекте, вместо прямого `apm install` используй
`python3 tools/run-apm-safe.py --audit-runner tools/apm-audit-ci`. Команда
проверяет исходники, проекции и `apm.lock.yaml` до установки и после неё. Для
подготовки версии, ещё не опубликованной в реестре, добавь
`--allow-unpublished-local-version`: он допускает только подтверждённые
локальные проекции пакета с тем же именем и не ослабляет проверку остальных
расхождений. После публикации проверяй установку без параметра в отдельном
тестовом проекте.

## Обновление зависимостей

`tools/run-apm-safe.py` выполняет `apm install --frozen` и не меняет версии
зависимостей: при изменении графа в `apm.lock.yaml` он останавливается. Если
задача требует обновить зависимости APM, выполни из корня проекта
с `PYTHONDONTWRITEBYTECODE=1`:

1. `python3 tools/validate-python-artifacts.py`. Барьер нужен до того, как APM
   скопирует исходники в проекции и закрепит их в `apm.lock.yaml`.
2. `apm update --yes`.
3. `python3 tools/apm-audit-ci`.
4. `apm run tests`. Проверки повторяют барьер до и после остальных проверок.
