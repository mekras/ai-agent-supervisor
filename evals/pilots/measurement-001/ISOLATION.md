# Изолированный стенд без моделей

Статус: реализован проверочный стенд Linux. Он не подключён к модельным
адаптерам и не разрешает запуск пилота. Пользовательские настройки не меняются.

## Назначение и граница доверия

Стенд проверяет требование паспорта: одинаковая явно заданная среда трёх
условий, отсутствие доступа к домашним настройкам и внешним эталонам.
Защищаемые данные — исходный репозиторий, оракулы, пользовательские настройки
и результаты соседних попыток. Проверяемый процесс считается недоверенным
относительно файлов и сети. Ядро Linux, bubblewrap, Python и системный `/usr`
остаются доверенной частью среды.

Поток данных: ведущий процесс копирует фикстуру и при необходимости коллекцию
в отдельный каталог → bubblewrap открывает только эту копию в `/work` →
детерминированная проба проверяет доступ и записывает результат → ведущий
процесс проверяет сохранность входов и удаляет свою временную копию.
Проба не решает предметные задачи и не выставляет оценки моделям.

| Угроза | Мера | Исполняемая проверка |
| --- | --- | --- |
| Чтение дома, исходников или оракулов | Корень файловой системы собирается из явных подключений, домашний каталог не подключается | Попытки чтения известных внешних путей, синтетического внешнего файла и ссылки на него |
| Наследование пользовательского окружения и сокетов | Пустая среда с небольшим списком разрешённых переменных, пустые `/home` и `/run`, закрытые посторонние дескрипторы | Проверка имён переменных и пустых каталогов |
| Попадание пользовательских шаблонов Git в копию до изоляции | Отдельный вызов Git с очищенной средой, отключёнными system/global config, пустым шаблоном и веткой `pilot` | Подставленный шаблон появляется при старой подготовке и отсутствует при новой |
| Доступ к внешней сети или процессам | Отдельные пространства имён сети и процессов, новый `/proc`, снятые capabilities | Отличие пространства сети, отказ подключения к порту ведущего процесса и доступа через его `/proc` |
| Изменение коллекции | Пакеты подключены только для чтения | Неуспешная запись внутри пакетов, повторное сравнение их манифеста |
| Перенос состояния между попытками | Новая рабочая копия и новый `/tmp` | Девять отдельных копий и повторная проба временного маркера |
| Зависание проверочной команды | Ограничение времени, остановка группы процессов, `--die-with-parent` | Принудительно задержанная проба завершается ошибкой |

При отсутствии bubblewrap, отказе создания изоляции или провале проверки
команда завершается с ошибкой. Продолжения без изоляции нет.

## Состав среды

- `/usr` и существующие системные `/bin`, `/lib`, `/lib64` доступны только для чтения.
- `/work` содержит копию одной фикстуры, новый `.git` без пользовательских шаблонов и `pilot-prompt.txt` с запросом штатного запускателя.
- Только условие `collection` содержит полные пакеты из `.apm/skills` в двух нативных каталогах.
- `/tmp`, `/dev` и `/proc` создаются заново. `/home` и `/run` пусты.
- Передаются только `PATH`, `LANG` и запрет записи байткода. Python может добавить `LC_CTYPE`.
- Проба `/probe.py` доступна только для чтения. Сведения о контрольных путях передаются ей на stdin.

Пути и ожидаемые хэши внутри пробы — данные теста изоляции. Их нельзя передавать
реальному кандидату: это раскрыло бы устройство опыта. Установка навыков и
запрос используют функции существующего запускателя. Подготовка Git в стенде
отдельная: общий `prepare_trial` пока сохраняет пользовательский фон. Модельный путь
`run_comparison` этим стендом не заменён и автоматически его не использует.

## Запуск проверки

Из корня репозитория:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 evals/pilots/measurement-001/isolation.py
```

Нужны Linux с разрешёнными пространствами имён, `/usr/bin/bwrap`,
`/usr/bin/python3` и Git. Ничего не устанавливается. Команда не принимает
произвольные команды, модели, ключи или параметры сетевого доступа.
Временные файлы создаются только в игнорируемом `eval-results` проекта.
Вывод содержит результаты девяти проб, версию bubblewrap и явные признаки
`model_calls: 0`, `live_adapter_connected: false`.

Эта проверка запускается отдельно от переносимого `apm run tests`, поскольку
требует Linux и bubblewrap. Отсутствие такого запуска нельзя считать успешной
проверкой изоляции на другой машине.

## Что ещё не проверено

Это проверка перечисленных границ, не доказательство защиты от любого
враждебного кода. Не проверены уязвимости ядра, исчерпание памяти, места на
диске и числа процессов. Ограничение времени не заменяет лимиты ресурсов.
Системный `/usr` общий для условий, но его полный состав не зафиксирован
как переносимый образ. Новая машина требует повторной проверки.

Реальные CLI, авторизация, их загрузка навыков, системные инструкции, учёт
расходов и судья пока не подключены. Сеть внутри стенда выключена целиком.
Для дальнейшего подключения моделей понадобится отдельное решение о безопасном
канале обращения к поставщику, без открытия кандидату домашней папки и эталонов.
Нельзя просто включить общую сеть или подключить домашний каталог и сохранить
прежний вывод о пройденной изоляции.

Записи `common_background` и статусы чернового плана остаются прежними:
среда реального модельного прогона ещё не подтверждена. Требования продукта
и публикуемая коллекция в этом шаге не изменены.
