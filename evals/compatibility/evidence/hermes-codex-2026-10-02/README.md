# Проверка Hermes → Codex — 2026-10-02

Один учебный сценарий на локальном кандидате поверх 2.6.13. Опубликованная
версия этим запуском не проверялась. Родитель получил обычную задачу составить
справку о трёх вымышленных сервисах с источниками и противоречиями.

- [Входные данные](inputs.json) содержат расхождения версии borey и срока хранения vega.
- [Ответ Hermes](answer.txt) охватывает три сервиса, оба расхождения и границу между журналами и всеми данными.
- [События приёмки](parent-acceptance-evidence.json) извлечены из сохранённой сессии Hermes. Событие 402 вызывает запись и проверку приёмки, событие 403 подтверждает код 0 и принятие результата.
- [Запись дочернего запуска](child-record.json) и [его ответ](child-answer.txt) сохранены без изменения. Пути в записи относятся к исходному контейнеру.
- [Отчёт проверки](report.json) фиксирует назначение родителя, подтверждённые клиентом параметры подагента, неизменность входов и хэши проверенной оснастки.

Родитель вызвал одного подагента, дождался завершения, сохранил приёмку и
выполнил её проверку до ответа. Независимая проверка записи тоже прошла.
Приёмка не дописывалась проверяющим задним числом.

Состояние агентов находилось в отдельных Docker volumes. Корневая файловая
система контейнера доступна только для чтения. Родитель запущен с `--yolo`
в пределах контейнера, подагент — с песочницей `read-only`. Эти условия не
являются рекомендацией отключать подтверждения в рабочей среде.

Проверены рабочее делегирование и запись приёмки на одном подготовленном
проекте. Установка и настройка с нуля, прочие задачи, устойчивость длительной
работы и экономия подписки этим прогоном не подтверждены. Высокое усилие
родителя зафиксировано командой запуска. Модель и низкое усилие подагента
подтверждены журналом и базой Codex на уровне клиента, не сервера.
