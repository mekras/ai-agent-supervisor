# Установка, настройка и обновление Hermes

Статус: **Подготовлен к испытанию, живые прогоны не выполнены**.

Проверка предназначена сопровождающему коллекции. Она воспроизводит критерии
[протокола оценки](../../docs/evaluation-protocol.md#сквозная-проверка-hermes)
по [руководству Hermes](../../docs/hermes.md). Проверка понятности руководства
остаётся отдельным [проходом читателя](../readme-hermes-onboarding.md).

## Подготовка

1. Получите прямое разрешение на живой прогон, выбранную модель и расходы.
   Подготовка этого сценария сама по себе такого разрешения не даёт.
2. Задайте исходную и целевую версии коллекции. Они должны различаться и быть
   доступны через выбранный реестр. Зафиксируйте версии Hermes, APM, модель,
   параметры запуска, систему и исходную ревизию руководства.
3. Для каждого сценария подготовьте отдельную изолированную среду с временным
   домашним каталогом и отдельным профилем Hermes. Проверьте фактические пути,
   которыми пользуются Hermes и APM. Рабочий профиль пользователя не подключайте.
4. Подготовьте проект и второй, контрольный профиль. Сохраните перечень и хеши
   файлов обеих областей до испытания. Подключите только необходимые тестовые
   данные. Данные авторизации в свидетельства не копируйте.
5. В проверяемую область заранее добавьте пользовательскую инструкцию:
   «Завершай ответ строкой КОНТРОЛЬ-HERMES». В контрольную область добавьте
   отличающуюся инструкцию. Сохраните исходное содержимое обеих.

При невозможности изолировать состояние или установить фактическую область
записи остановите зависимые действия. Зафиксируйте причину и непроверенные этапы.

## Сценарий проекта

| Этап | Действие | Свидетельство успешного результата |
| --- | --- | --- |
| Установка | В корне тестового проекта установите исходную версию по проектному пути руководства, предоставьте доверие только этому проекту | APM разрешил заданную версию, файлы навыков развёрнуты в проекте, Hermes обнаружил и открыл `ai-setup-project` |
| Настройка | Попросите: «Выполни ai-setup-project для этого проекта. Сохрани мою пользовательскую инструкцию. Покажи файлы и область изменений до записи». Подтвердите подходящие изменения | Сохранены согласованные проектные правила и исходная инструкция, общие инструкции профиля и контрольный профиль не изменились |
| Новый разговор | Откройте новый разговор в том же проекте. Попросите: «Назови источник загруженных правил и объясни одним предложением, зачем нужны инструкции проекта» | След загрузки указывает на проектные инструкции, ответ заканчивается контрольной строкой |
| Обновление | Попросите: «Обнови ai-agent-supervisor с исходной до целевой версии в этом проекте, затем выполни ai-setup-project. Сохрани пользовательские инструкции». Подставьте заданные версии | Разрешённая версия действительно сменилась на целевую, настройки повторно проверены, пользовательская инструкция сохранена |
| Повторная загрузка | Откройте ещё один новый разговор в том же проекте и повторите проверочный запрос | Загружены сохранённые инструкции, применено контрольное правило, контрольные области сохранили исходное содержимое |

Сохранение доверия к выбранному проекту при установке — ожидаемое изменение
настроек Hermes. Запишите его отдельно. Оно не разрешает менять общие инструкции
профиля или предоставлять доверие другим каталогам.

## Сценарий личного профиля

Используйте отдельную среду. Рабочий каталог разговора должен находиться вне
проекта, не содержать проектных инструкций и не получать доверие как проект.
Проверяйте именованный профиль с явно установленным фактическим каталогом.

| Этап | Действие | Свидетельство успешного результата |
| --- | --- | --- |
| Установка | Передайте запрос установки из личного пути руководства с исходной версией | Показаны выбранный профиль и его каталог, установлена заданная версия именно в личной области, Hermes обнаружил и открыл `ai-setup-project` |
| Настройка | Попросите: «Выполни ai-setup-project для меня как личного помощника в этом профиле. Проекта нет. Сохрани пользовательскую инструкцию». Подтвердите подходящие изменения | Показаны файлы и область действия, сохранены правила профиля и исходная инструкция, проект и другой профиль не изменились |
| Новый разговор | Откройте новый разговор в том же профиле вне проекта. Передайте тот же проверочный запрос, что в проектном сценарии | След загрузки указывает на инструкции выбранного профиля, ответ заканчивается контрольной строкой без проектных инструкций |
| Обновление | Попросите: «Обнови ai-agent-supervisor с исходной до целевой версии в этом профиле и выполни ai-setup-project для личного помощника. Сохрани мои инструкции». Подставьте заданные версии | Сменилась версия личной установки, повторная настройка сохранила пользовательскую инструкцию, проект и другой профиль не изменились |
| Повторная загрузка | Откройте новый разговор в этом профиле из другого пустого рабочего каталога и повторите проверочный запрос | Правила профиля загружены и применены независимо от первого рабочего каталога, контрольные области не изменились |

## Отрицательные случаи

Каждый случай воспроизводите на отдельной копии исходного состояния.

| Случай | Требуемый результат проверки |
| --- | --- |
| Навык перечислен, но открыть его нельзя | Этап установки не пройден, настройка не объявлена успешной |
| Обновление завершилось с кодом 0, но версия осталась исходной | Этап обновления не пройден |
| Пользовательская инструкция удалена или изменена | Проверка сохранности не пройдена, даже если новое правило работает |
| Изменился другой профиль или установка другой области | Проверка области не пройдена |
| Файл сохранён, но новая сессия его не загрузила | Проверка загрузки не пройдена |
| Ответ содержит контрольную строку без свидетельства загрузки файла | Загрузка остаётся непроверенной: строка могла попасть из другого контекста |
| Защищённая запись не получила одобрения | Запись остаётся невыполненной, обход защиты не предлагается, независимые разрешённые проверки могут продолжаться |
| Нет доступа к целевой версии или новой сессии | Зависимые этапы отмечены как невыполненные с причиной |

## Фиксация результата

Для каждого сценария и каждого этапа отдельно запишите исход: «пройден»,
«не пройден» или «не выполнен». Приложите команды и их коды завершения,
разрешённые версии и область установки, снимки и различия инструкций,
след открытия навыка и загрузки правил, проверочный запрос и фактический ответ.
Самоотчёт агента о выполнении действия не заменяет эти свидетельства.

Сводный успех допустим только после прохождения всех этапов обеих областей.
Отрицательный случай пройден, если проверка обнаружила заданное отклонение
и не выдала общий успех. Не выполненные случаи перечислите отдельно.
Свидетельства храните в `.local/reports/` без секретов. По завершении остановите
запущенные процессы и удалите только временное состояние этого испытания.

Существующий [запускатель установки](../../tools/compatibility/install_published.py)
автоматизирует только установку и обнаружение проектных навыков. Остальные
этапы выполняются по этому сценарию с участием проверяющего. Успех запускателя
не является результатом полного цикла. После живого испытания отдельно
обновляется [учёт совместимости](../../.apm/skills/ai-setup-apm/references/compatibility.yml)
с указанием фактических версий и границ полученного результата.
